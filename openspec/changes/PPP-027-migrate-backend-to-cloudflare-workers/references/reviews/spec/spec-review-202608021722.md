### Issue 3: tasks 4.7 / design D12 のコメント書き換え範囲が `waitForContainerReady` 付近に限定されており、同種の記述が 2 箇所残る

- **Severity**: Minor
- **Location**: `tasks.md`（L42）/ `design.md`（L107）
- **Description**: 両者とも「`waitForContainerReady` 付近のコメントに残る `Netlify 同期 Function の実行時間制限` という記述を書き換える」としているが、`backend/netlify/functions/threads_post.js` で同趣旨の記述は 3 箇所ある。

  ```
  L9:   // Netlify 同期 Function の実行時間制限（10 秒）に対する全体予算。
  L56:  // deadline は絶対時刻（ミリ秒）。Netlify 同期 Function の実行時間制限に収めるため有限に打ち切る。
  L264: // Netlify 同期 Function の実行時間制限に収めるための全体予算（本投稿と PR ゴースト投稿で共有する）
  ```

  タスクの文言どおりに実施すると L56 のみが直り、予算定数の定義箇所（L9）と `deadline` 算出箇所（L264）に Netlify 前提の根拠記述が残る。定数値そのものは 4.7 で必ず触るため実害は小さいが、「基盤名依存の根拠記述を除去する」という 4.7 の目的が部分的にしか達成されない。
- **Suggestion**: 4.7 および D12 の記述を「`threads_post` 内に残る `Netlify 同期 Function の実行時間制限` に基づく根拠コメント（予算定数の定義箇所・`waitForContainerReady`・`deadline` 算出箇所の 3 箇所）を、Workers の制約に基づく記述へ書き換える」へ改める。

### Issue 4: `backend-hosting` の「本アプリが扱う最大枚数」という根拠付けが実装と一致しない

- **Severity**: Minor
- **Location**: `specs/backend-hosting/spec.md`
- **Line**: L48
- **Description**: Iteration 2 の Issue 3（参照先不在）を受けて「1 投稿あたり 10 枚（`threads-posting` capability が定める Threads のカルーセル上限であり、**本アプリが扱う最大枚数**）」と自己完結化されたが、後半の括弧書きは事実と一致しない。`frontend/src/lib/ImagePreview.svelte` L171 の `<input type="file" multiple>` に枚数制限は無く、`misskey_post.js` / `bluesky_post.js` にも枚数上限のガードは無い（11 枚以上を拒否するのは `threads-posting` の Threads 経路のみ）。したがって Misskey・Bluesky へは 10 枚を超える投稿が構造上あり得る。

  なお「10 枚までは壁時計上限を理由に失敗させてはならない (SHALL NOT)」という要件自体は 10 枚という具体値で閉じており、テスト可能性・検証可能性は確保されている（Iteration 2 の Issue 3 の趣旨は満たされている）。問題は根拠の記述のみ。
- **Suggestion**: 「1 投稿あたり 10 枚（`threads-posting` capability が定める Threads のカルーセル上限。本要件が保証する最小の対応枚数とする）」のように、アプリの実装上の上限ではなく「本要件が保証する枚数」として言い直す。
