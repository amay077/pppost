## Minor Issues

### Issue 1: `window.built_at` が空文字の場合の挙動が spec に未定義
- **Severity**: Minor
- **Location**: `specs/version-display/spec.md`（Requirement: SPA 更新の検知）
- **Line**: 4
- **Description**: `MainContent.svelte:17` は `(window as any)['built_at'] ?? ''` でフォールバックするため、何らかの理由で `window.built_at` が空文字となった場合、文字列比較の結果「サーバ側が新しい」と判定され、誤って「更新」ボタンが表示され続ける可能性がある。spec には built_at が取得できない場合の挙動が定義されていない。
- **Suggestion**: 「現在の SPA の `built_at` が取得できない（空文字等）場合は、更新は利用可能と判定しない（SHALL）」旨の一文を Requirement またはシナリオに追加する。

### Issue 2: サーバ側 `built_at` が現在より古い場合のシナリオが未定義
- **Severity**: Minor
- **Location**: `specs/version-display/spec.md`
- **Line**: 12-16
- **Description**: 「新バージョンが存在する場合」と「バージョンが最新の場合」の 2 シナリオのみ。サーバ側が古い場合（デプロイ失敗・ロールバック等）の挙動は「サーバ側が新しい場合のみ判定（SHALL）」から導出可能だが、明示されていない。
- **Suggestion**: 「サーバ側の `built_at` が現在の SPA の `built_at` より古い場合、『更新』ボタンは表示されない」シナリオを追加するか、最新シナリオに統合して明記する。

### Issue 3: `version.json` の fetch パス解決方式が spec に未記載
- **Severity**: Minor
- **Location**: `specs/version-display/spec.md` / `proposal.md`
- **Line**: spec.md 4 / proposal.md 14
- **Description**: fetch する `version.json` の URL が相対パスか絶対パスか未定義。動作は `vite.config.ts` の `base: "./"` とデプロイ先パス（`/pppost/` 等）に依存するため、パス解決の前提を明記しないと実装時に解釈の揺れが生じる。
- **Suggestion**: 「`version.json` は現在の index.html と同一ディレクトリの相対パスで取得する」ことを proposal.md または spec に明記する。

### Issue 4: 更新後の URL に `?v=<時刻>` クエリが残存する
- **Severity**: Minor
- **Location**: `specs/version-display/spec.md`（Requirement: SPA の更新）
- **Line**: 26-32
- **Description**: `location.href = location.pathname + '?v=' + Date.now()` により、更新後に URL へ `?v=` クエリが残る。ブックマークや共有でこの URL が永続化されると、以降のアクセスでキャッシュバスター付き URL が使い続けられる。機能上の障害はないが、仕様としての取り扱いが未定義。
- **Suggestion**: 更新後のクエリ除去（例: `history.replaceState` での整形）の要否を明記する。不要とする場合は、その旨を Non-Goals 相当の注記として提案時に残す。

### Issue 5: シナリオごとの検証タスクが手動確認に集約されている
- **Severity**: Minor
- **Location**: `tasks.md`
- **Line**: 12-13
- **Description**: 3 シナリオ（新バージョン存在時 / 最新時 / 取得失敗時）の検証が tasks.md の 2.3「手動確認」に集約されており、各シナリオの個別検証が明確ではない。
- **Suggestion**: 2.3 をシナリオごとの小項目（2.3.1 新バージョン存在時 / 2.3.2 最新時 / 2.3.3 取得失敗時）に分割する。
