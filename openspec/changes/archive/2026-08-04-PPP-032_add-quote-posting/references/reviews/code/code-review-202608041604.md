## Issues

### Issue 1: Bluesky のリクエストログに quote_to_id が含まれない
- **Severity**: Minor
- **Location**: `backend/netlify/functions/bluesky_post.js:84`
- **Description**: `console.log('Bluesky post request:', { text, images: images?.length, reply_to_id })` に `quote_to_id` が含まれていない。引用投稿の動作確認時に引用元 ID がログに残らない。
- **Suggestion**: `quote_to_id` をログに含める（`{ text, images: images?.length, reply_to_id, quote_to_id }`）。

### Issue 2: 引用元解決時の例外は大枠 catch で 500 になる
- **Severity**: Minor
- **Location**: `backend/netlify/functions/bluesky_post.js:365-382`
- **Description**: `agent.getPostThread` が例外を投げる場合（例: URI 不正・PDS エラー）、`quoteEmbed === null` の 400 分岐には入らず、handler の大枠 catch で 500 になる。仕様（「引用失敗時はエラー一覧に Bluesky を含めて通知」）は満たすが、引用元不存在（400）とその他エラー（500）の種別が区別されない。
- **Suggestion**: `getPostThread` を try-catch で包み、失敗時も `null` を返して 400 に統一する（またはエラー種別をログで区別）。

### Issue 3: 本文なし引用リノートが既存の text or images required チェックで不可
- **Severity**: Minor
- **Location**: `backend/netlify/functions/misskey_post.js:55-61`
- **Description**: 引用元のみ指定（本文なし・画像なし）のリクエストは既存チェック `text or images required` で 400 になる。ただし、フロントエンドの投稿ボタンは本文または画像が無いと disabled のため、UI 上この状態は発生しない。また、既存 spec（「本文と添付ファイルの双方が空のノートを受け付けない」）とも矛盾しない。
- **Suggestion**: 仕様の範囲内であり対応不要。引用投稿タスク（実機確認）で本文なし引用が不可であることを確認済みとして記録に残すと良い。
